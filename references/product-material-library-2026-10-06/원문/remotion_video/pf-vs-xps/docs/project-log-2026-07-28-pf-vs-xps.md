# PF보드 vs 아이소핑크 쇼츠 개발 기록

## 프로젝트 개요

- **목적**: LX PF보드와 아이소핑크(XPS) 단열재를 비교해, "같은 단열 성능이라도 PF보드가 더 얇고, 그만큼 공간을 더 확보할 수 있으며, 초기 시공비가 조금 더 들더라도 장기적으로는 냉난방 비용까지 함께 고려해야 한다"는 메시지를 전달하는 대산(Daesan) 브랜드 유튜브 쇼츠 영상 제작
- **최종 결과**: Scene1~5 대본·타이밍·음성을 모두 확정하고 최종 MP4를 렌더링, GitHub 저장소에 반영 완료
- **렌더 정보**
  - 1080×1920
  - 30fps
  - 35.285초
  - 약 2.93MB

## 개발 타임라인

### 1. 영상 구성

5개 씬으로 구성:
- **Scene1**: 훅 — "같은 단열 성능인데, 두께는 왜 다를까요?"
- **Scene2**: PF보드가 같은 성능에서 더 얇은 이유(열전도율)
- **Scene3**: 얇아진 만큼 실내 공간을 더 확보할 수 있다는 메시지
- **Scene4**: 25평 기준 초기 시공비 차이 vs 장기 냉난방 비용을 함께 고려해야 한다는 균형 메시지
- **Scene5**: 브랜드 엔딩 + CTA(신뢰 문구 → 대량구매는 대산 → 로고)

Scene1~5 최종 대본을 모두 확정했다.

### 2. TTS 개선

- MODEL: `gpt-4o-mini-tts`
- VOICE: `onyx`
- Instructions를 "한국어 TV 정보 프로그램 진행자의 내레이션처럼" 읽도록 개선 — 처음부터 끝까지 같은 사람처럼 톤·에너지·속도를 일정하게 유지하고, 발음은 또렷하게, 문장 끝은 흐리지 않도록 명시
- 개선된 동일 Instructions로 Scene1~5 전체 TTS를 재생성해 씬 간 톤 편차를 제거하고 통일

### 3. Scene2 개선

- 결론 문구("같은 단열 성능을 / 더 얇은 두께로 구현")에 추가했던 2차 강조 펄스(160~172f, scale 1.00→1.03→1.00)를 제거하고 1차 강조만 유지
- **이유**: Scene2 오디오 종료 시점이 약 159f였는데 2차 펄스는 160f에 시작 — 즉 음성이 이미 끝난 뒤에 강조가 시작되는 구조가 되어, "음성이 재생되는 동안 화면 리듬을 살린다"는 원래 목적과 어긋났기 때문

### 4. Scene4 개선

- 로컬 Whisper 미설치로, 이미 사용 중이던 OpenAI API 키로 전사(transcription) API를 호출해 scene4.mp3의 **단어 단위 실제 타임스탬프**를 확보(글자수 비율 추정 방식 폐기)
- **intro2** 동기화: hold를 실제 발화("시공비는 아이소핑크가 약 20만 원 저렴합니다") 종료 시점까지 연장(106f→139f, exit 113f→146f)
- **stage1** 동기화: "하지만"의 실제 발화 구간(165~171f)에 정확히 맞춰 재배치
- **stage2**를 그룹A("오래 쓰는 단열재")/그룹B("냉난방 에너지까지" / "함께 고려하세요")로 분리해, 기존 3줄 동시 등장 대신 실제 발화 흐름에 맞춰 순차 등장하도록 구조 변경(레이아웃·폰트·문구는 불변)
- **PF보드 강조 애니메이션** 기준을 기존 `stage2.enterStart`에서 `stage2.groupA.enterStart`로 변경 — 의미상 첫 결론 문구 등장과 연결되도록 유지
- 최종 프레임: intro1 불변, intro2/stage1/stage2(그룹A·B)를 실제 발화 타이밍 기준으로 재정리, 그룹A는 최종 미세조정으로 174~181f 확정

### 5. Scene5 개선

- CTA 문구 변경

  기존
  > "제품 선택이 고민되시나요? 대산이 함께 확인해드립니다."

  ↓

  최종
  > "어떤 제품이 맞을지 고민되신다면, 대산이 함께 도와드리겠습니다."

- 변경된 문구로 Scene5 TTS만 재생성(5.448s)
- 공식에 따라 프레임 재계산: `ceil((5.448+0.6)×30) = 182f`

### 6. QA

- 매 코드 수정마다 `npx tsc --noEmit` PASS
- 매 코드 수정마다 `npm run build` PASS
- Scene4는 실제 전사(Whisper/OpenAI) 기반으로 자막-음성 정합 검증
- 각 씬 음성 길이를 ffprobe로 실측 검증
- ffmpeg `silencedetect`로 무음 구간·리딩/트레일링 무음 검증(비정상적으로 긴 끊김 없음 확인)
- 씬 경계 및 자막-PF보드 강조 겹침 여부를 스틸 프레임 캡처로 시각 충돌 검증

### 7. 렌더

- 1·2차 렌더 시도 모두 "Loading Pretendard 500" 폰트 로딩이 28초 내에 완료되지 않는 delayRender 타임아웃으로 실패(각각 793, 1034번 프레임에서 발생 — 리소스 경합으로 추정)
- 소스 코드는 수정하지 않고 렌더 실행 옵션만 조정: `--concurrency=2 --timeout=90000`
- 3차 시도에서 최종 성공 (1057/1057 프레임, `out/pf-vs-xps-final-2026-07-28.mp4`)

## 이번 프로젝트에서 얻은 교훈

### 잘된 점

- 글자수 추정 대신 **실제 전사(Whisper/OpenAI) 기반 자막 동기화**로 훨씬 정밀하게 음성-자막을 맞출 수 있었음
- TTS Instructions를 하나로 통일해 **씬 간 톤 편차 문제**를 근본적으로 해결
- CTA 문구를 판매 멘트가 아닌 상담 초대 톤으로 다듬어 **CTA 개선**
- 레이아웃·문구는 고정한 채 타이밍 상수만 반복 조정하는 방식으로 **Scene 단위 반복 개선**을 안전하게 진행(클리핑·레이아웃 붕괴 리스크 최소화)

### 다음 프로젝트에서 기본으로 사용할 것

- 동일한 TTS Instructions(TV 정보 프로그램 톤 템플릿)를 프로젝트 시작 시점부터 적용
- Whisper(OpenAI 전사 API) 기반 자막 동기화를 기본 워크플로우로 채택
- Scene별 오디오 길이 자동 계산 공식: `ceil((오디오 길이 + 0.6초) × 30fps)`
- Render 옵션 `--concurrency=2 --timeout=90000`을 기본값으로 사용(Pretendard 폰트 로딩 타임아웃 회피)

### 개선 과제

- 브라우저 자동 미리보기 연결(Claude in Chrome 확장 미연결로 이번 프로젝트 내내 실제 재생 기반 검증을 하지 못하고 객관적 지표로만 대체한 제약이 반복됨)
- 자막 타이밍 자동 생성(현재는 프레임 값을 수동으로 계산·입력하는 방식)
- Whisper 기반 자동 싱크 도구화(매번 1회성 스크립트를 새로 작성하는 대신 재사용 가능한 도구로 정리)
