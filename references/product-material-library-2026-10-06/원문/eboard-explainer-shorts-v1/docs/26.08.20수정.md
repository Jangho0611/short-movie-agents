# 26.08.20 수정 기록

## 1. 프로젝트 개요

- 주제: 복합단열재 이보드의 구조, 마감 방식별 구분, 적용 위치와 시공 주의사항
- 영상 목적: 실제 제품 reference와 승인 이미지를 바탕으로 이보드의 핵심 정보를 짧고 정확하게 전달

- 최종 러닝타임: 950프레임 / Remotion 기준 39.583초
- 렌더 사양: 1080×1920, 24fps, H.264, AAC 48kHz stereo
- 최종 승인 Preview: `public/assets/video/eboard-explainer-full-preview-v7.mp4`
- 최종 파일: `public/assets/video/eboard-explainer-final.mp4`

## 2. Scene 1~7 최종 구성

### Scene 1 — 공정 차이 Hook

- 역할: 단열 시공 후 별도 석고보드 공정에 대한 질문으로 이보드의 차이를 제시
- 방식: Flow
- asset: `public/assets/video/scene01-flow-trimmed-v1.mp4`
- 승인 기준 이미지: `public/references/scene01-base-v1.png`
- TTS: `단열 시공 후 석고보드까지? 이보드는 조금 다릅니다.`
- 자막: `단열 시공 후 / 석고보드까지?` → `이보드는 / 조금 다릅니다`
- 특이사항: 캐릭터 얼굴·눈·입·외곽선이 안정적인 프레임까지만 사용하고 Flow 원본 오디오는 제거했다.

### Scene 2 — 복합단열재 구조

- 역할: 실제 단면을 바탕으로 XPS 심재, PP 표면판, 부직포의 결합 구조 설명
- 방식: Remotion
- asset: `public/references/scene02-base-v1.png`, `public/references/products/eboard-cross-section-main-v1.jpeg`, `public/references/products/eboard-cross-section-detail-v1.jpeg`
- TTS: `이보드는 XPS 단열재에, PP 표면판과 부직포가 결합된 복합단열재입니다.`
- 자막: `이보드는 어떻게 / 구성돼 있을까?`
- 특이사항: TTS 발화와 네임택 강조 순서를 `XPS 심재 → PP 표면판 → 부직포`로 일치시켰다.

### Scene 3 — 공정 비교

- 역할: `XPS + 석고보드`와 `이보드` 비교
- 방식: Remotion
- asset: `public/references/scene03-base-v1.png`
- TTS: `표면재가 결합돼 있어, 별도의 석고보드 공정을 줄이고 마감으로 이어갈 수 있습니다.`
- 자막: `별도 석고보드 공정을 / 줄일 수 있습니다`
- 라벨: 좌측 `XPS + 석고보드`, 우측 `이보드`
- 특이사항: 제품 질감을 가리지 않도록 라벨을 제품 위가 아니라 제품 아래의 깨끗한 여백에 배치했다.

### Scene 4 — 마감 방식별 표면 비교

- 역할: 도배용과 페인트용 이보드의 표면 구분
- 방식: Remotion
- asset: `public/references/scene04-base-v1.png`
- TTS: `겉보기엔 비슷하지만, 도배용과 페인트용은 표면이 다릅니다.`
- 자막: `최종 마감에 따라 / 표면이 달라집니다`
- 라벨: 좌측 `도배용`, 우측 `페인트용`
- 특이사항: 실제 차이가 미묘하므로 AI로 차이를 과장하지 않았다. 제품 표면 위 라벨을 금지하고 아래 여백으로 옮겼다. Flow에서 캐릭터 크기를 반복 조정하는 방식이 실패해 승인 이미지와 Remotion 비교 구성으로 확정했다.

### Scene 5 — 적용 공간

- 역할: 외기와 맞닿는 벽체 등 내단열이 필요한 위치의 적용 예시
- 방식: Flow + Remotion 자막
- asset: `public/assets/video/scene05-flow-v1.mp4`, `public/references/scene05-base-v1.png`
- TTS: `이보드는 외기와 맞닿는 벽체나 발코니 등, 내단열이 필요한 곳에 활용할 수 있습니다.`
- 자막: `외기와 맞닿는 벽체 / 내단열이 필요한 곳에 활용`
- 특이사항: TTS는 `발코니 등` 뒤에 0.18초의 짧은 내부 호흡을 둔 승인 파일을 사용한다. Flow 144프레임/6.000초 전체를 playbackRate 1.0으로 재생하고 마지막 정상 프레임을 13프레임/0.542초 hold한다. 추가 push-in·scale·crossfade 없이 Scene 6으로 hard cut한다. v5의 hold 증가와 v6의 보정 효과를 폐기하고 v4 영상 처리 방식으로 복원한 v7이 최종 승인본이다. Flow 원본 오디오는 muted다.

### Scene 6 — 시공 마무리 팁

- 역할: Small Daesan이 이음부 처리 주의사항을 전달
- 방식: Remotion
- asset: `public/references/scene06-base-v1.png`, `public/references/characters/small-daesan-canonical-v1.png`
- TTS: `마감 전에는 꼭! 이음부를 꼼꼼하게 처리해 주세요.`
- 자막: `마감 전에는 꼭!` → `이음부 처리는 / 꼼꼼하게`
- 특이사항: 제품 설명 Scene보다 Small Daesan의 비중을 높인 마무리 장면이다. Scene 5의 남은 발화와 겹치지 않도록 Scene 6 TTS를 화면 시작 4프레임 뒤에 재생한다.

### Scene 7 — 대산 엔딩

- 역할: 기존 대산 브랜드 엔딩
- 방식: 기존 Remotion 엔딩 재사용
- asset: `public/assets/logos/daesanlogo2.png`, `public/assets/audio/scene07-ending-tts.mp3`
- TTS: `자재 선택이 고민된다면, 대산이 도와드립니다.`
- 화면 문구: `GS건설 3년 연속 납품업체 / 자재 대량 구매 / 대산`
- 특이사항: 기존 엔딩의 로고, 비주얼, 모션, 136프레임 duration과 승인 TTS를 그대로 사용했다.

## 4. 다음 영상 재발 방지 운영 규칙

### 4-1. Scene 제작 순서

1. 핵심 메시지 확정
2. 실사/reference 확정
3. 기준 이미지 생성
4. 사용자 승인
5. Flow/Veo 필요 여부 판단
6. 영상 생성/승인
7. Remotion 적용
8. 전체 TTS 대본 확정
9. 통합 TTS QA
10. Scene duration/싱크
11. 전체 Preview QA
12. 최종 렌더

이미지 승인 전에 Remotion을 제작하지 않고, TTS 대본 승인 전에 duration을 확정하지 않는다.

### 4-2. Flow 사용 최소화

Flow에서 제품, 캐릭터, 크기, 이동, 제품 모션을 한 번에 해결하지 않는다. 기준 이미지에서 가능한 요소를 먼저 고정하고 Flow에는 꼭 필요한 동작만 맡긴다.

### 4-3. Flow 캐릭터 크기 조절 반복 금지

캐릭터 크기와 위치는 기준 이미지에서 먼저 확정한다. Flow는 최소 모션만 담당하며, 같은 제어가 2회 이상 실패하면 Remotion 또는 다른 방식으로 전환한다. Scene 4의 Small Daesan 크기 반복 실패를 대표 사례로 삼는다.

### 4-4. 승인본 우선 복원

새 수정본이 나빠지면 최신 버전이 아니라 사용자가 마지막으로 승인한 버전으로 복귀한다. Scene 5는 `v4 자연스러움 → v5 hold 증가로 끊김 → v6 push-in/crossfade로 악화 → v7에서 v4 처리 복원` 과정을 거쳐 최종 승인됐다.

### 4-5. Flow 원본 움직임 존중

자연스러운 Flow 위에 push-in, zoom, crossfade를 문제 해결 수단으로 무조건 추가하지 않는다. 먼저 이전 승인본과 현재 코드의 재생 방식, duration, hold 차이를 조사한다.

### 4-6. Flow 길이와 TTS 길이를 강제 일치시키지 않기

TTS 때문에 hold가 길어진다면 Scene duration부터 늘리지 않는다. TTS 문장, 영상의 자연스러운 종료점, 실제 hold 길이, 화면과 음성 전환의 분리 가능성을 먼저 검토한다.

### 4-7. TTS 통합 QA 필수

Scene별 TTS 외에 전체 Scene 순서로 연결한 `full-tts-qa` 파일을 만든다. 사용자가 전체 발화 흐름을 한 번에 승인한 뒤 영상에 적용한다.

### 4-8. TTS 쉼표를 맹신하지 않기

쉼표는 실제 호흡을 보장하지 않는다. 문장 자체 수정이 우선이며, 해결되지 않으면 Part를 나누고 0.15~0.25초의 짧은 호흡을 사용한다. `단열하고 또`의 강제 무음은 문장 자체를 `단열 시공 후 석고보드까지?`로 바꿔 해결했고, Scene 3의 `있어별도의`와 Scene 5의 `발코니 등내단열`은 짧은 내부 호흡으로 해결했다.

### 4-9. TTS와 화면 강조 순서 동일

기술 구조 Scene은 최종 TTS 발화 순서대로 강조한다. Scene 2의 최종 기준은 `XPS → PP 표면판 → 부직포`다.

### 4-10. 라벨은 제품 표면을 가리지 않기

실사 질감이 중요한 자재의 라벨은 제품 아래 또는 깨끗한 여백에 배치한다. Scene 3·4를 대표 사례로 삼는다.

### 4-11. 제품 정확도 > 디자인

AI 결과가 시각적으로 좋아도 실제 자재의 표면, 단면, 구조가 틀리면 사용하지 않는다. 우선순위는 `실제 촬영 reference → 승인 제품 이미지 → 디자인 스타일`이다.

### 4-12. 반복 이미지 수정 제한

한 번에 수정 대상 하나만 지정하고 나머지는 LOCK한다. 캐릭터와 제품을 번갈아 수정해 승인 요소가 퇴보하는 패턴을 피하며, 2~3회 실패하면 기존 승인본으로 복귀한다. Scene 4를 대표 사례로 기록한다.

### 4-13. Preview별 변경 범위 기록

v1, v2, v3처럼 Preview마다 변경한 항목을 기록하고 서로 무관한 수정사항을 한 버전에 섞지 않는다.

### 4-14. 비용 절약

Flow, Veo, Vertex 사용 전에 기준 이미지 승인, reference 확인, prompt QA, 길이, 성공 조건을 확인한다. 같은 문제로 2회 이상 재생성하면 다른 도구로 전환할지 검토한다.

### 4-15. 최종 Git 저장 전 자산 정리

프로젝트 최종 마무리 시 실패 이미지·실패 영상·중간 Preview·폐기 TTS를 정리한 뒤 Git commit/push한다. 삭제 전에 최종 렌더와 코드 참조 여부, 더 나은 승인본 존재 여부와 작업기록 보존 여부를 확인한다.

## 5. 오늘 검증된 비주얼그레마

### 5-1. Figma-inspired Shorts 기본 구조

9:16 세로형 warm off-white canvas를 기본으로 한다. 상단 20~30%에 넓은 여백을 두고 Scene마다 pastel accent 하나와 rounded color block을 사용한다. 큰 검정 타이포는 최대 2줄로 제한한다. gradient와 glow는 기본적으로 사용하지 않으며 웹 UI보다 제품과 캐릭터가 주인공으로 보여야 한다.

### 5-2. 한 Scene 한 컬러

한 장면에 여러 pastel 컬러를 섞지 않고 Scene별 accent를 하나만 사용한다.

### 5-3. 실사 제품 + 그래픽 분리

제품 사진과 질감은 실사를 우선한다. 텍스트, 라벨, 화살표와 정보 강조는 생성 이미지에 굽지 않고 Remotion에서 처리한다.

### 5-4. 단면 Scene

실제 촬영 reference를 우선하고 AI가 구조를 재해석하지 않게 한다. 실제 층 순서를 보존하고 라벨은 후편집하며 제품이 화면의 주인공이어야 한다.

### 5-5. 비교 Scene

비교 대상 수를 단순화하고 좌우 대응과 가운데 여백을 명확히 한다. 라벨은 제품 아래에 두고 제품 표면을 텍스트로 가리지 않는다.

### 5-6. 미세한 제품 차이

도배용과 페인트용처럼 육안 차이가 작은 제품은 AI로 차이를 과장하지 않는다. `겉보기엔 비슷하다`는 사실 자체를 비교 Scene의 시각 문법으로 활용한다.

### 5-7. 적용 공간 Scene

장소 이름만 보여주지 말고 자재가 그 위치에 쓰이는 기능적 맥락이 읽혀야 한다. 예시는 외기와 맞닿는 벽체, 창호 인접 벽체, 단열 필요 영역이다.

### 5-8. 캐릭터 역할

제품 정보 Scene에서는 제품이 주인공이고 Small Daesan은 보조다. 마무리 Scene에서는 Small Daesan의 비중을 조금 높일 수 있다.

### 5-9. 캐릭터 + 실사 혼합

제품은 photorealistic하게, Small Daesan은 flat 2D editorial/webtoon으로 유지한다. 전체를 CGI 스타일로 통일하지 않는다.

### 5-10. Flow Start Frame

Flow 기준 이미지는 움직임이 없어도 화면이 성립하는 완성된 첫 프레임이어야 한다.

### 5-11. Flow 모션

제품은 가급적 static으로 유지하고 캐릭터의 시선·손짓과 최소 카메라 이동만 허용한다. final hold를 사용할 수 있지만 late-frame drift와 얼굴·제품 변형을 반드시 확인한다.

## 최종 QA 결과

- 최종 파일은 1080×1920, 24fps, H.264, AAC 48kHz stereo다.
- 전체 950프레임과 video/audio stream을 확인했다.
- 전체 디코딩을 오류 없이 통과했다.
