2. 이번 2편 주제
==================================================

제목:
「벽 두께가 다르면 문틀은 어떻게 발주할까?」

타깃:
일반 소비자보다는
- 인테리어 업체
- 현장 담당자
- 자재 발주 담당자
를 겨냥한 B2B 발주 정보형 콘텐츠.

핵심 질문:
현장 벽체 두께가 다를 때 문틀 폭은 무엇을 기준으로 결정하고 발주해야 하는가?

핵심 메시지:
벽체 두께만 보고 문틀 폭을 정하지 않는다.

벽체 두께 확인
→ 최종 마감 두께 확인
→ 현장에 필요한 문틀 폭 판단
→ 선택 제품의 실제 공급/운영 규격 확인
→ 발주

「벽체 두께 + ○mm = 문틀 폭」처럼 모든 현장에 적용되는 고정 계산식은 만들지 않는다.

현장마다 타일 등 최종 마감재와 마감 구성이 달라질 수 있기 때문에 실제 마감 후 필요한 폭을 고려해야 한다.

3. 이번 영상에 사용할 확정 현업 사례
==================================================

실제 발주 현업 확인 사례:

조건:
- 벽체 115mm
- 타일 마감
- 발포문틀 사용

결과:
→ 발포문틀 130바 필요

중요:
이 사례를
「115mm 벽체 = 무조건 130mm 문틀」
이라는 범용 공식으로 표현하지 않는다.

반드시
「115 벽체 + 타일 마감 + 발포문틀」
이라는 조건을 함께 보여준다.

핵심은 벽체 자체의 두께만 보는 것이 아니라 최종 마감 두께까지 고려해야 한다는 것이다.

==================================================
4. 발포문틀 운영 규격
==================================================

영림 공식 Door Frame 자료에서 확인한 발포문틀 운영 폭을 사용한다.

일반형:
110 / 130 / 140 / 155 / 175 / 195 / 210 / 230 / 245mm

와이드형:
110 / 140 / 155 / 175 / 195 / 210 / 230 / 245mm

슬림와이드형:
110 / 140 / 155 / 175 / 195 / 210 / 230 / 245mm

중요:
- 일반형에는 130mm가 있다.
- 확인한 공식 운영표상 와이드형/슬림와이드형에는 130mm가 없다.
- 세 타입의 규격이 모두 동일하다고 표현하지 않는다.
- 숫자를 TTS로 전부 읽지 않는다.
- 규격표는 Remotion 정보 그래픽으로 보여주는 것을 우선한다.

Scene 3의
「115 벽체 + 타일 마감 → 발포문틀 130바」
사례와 Scene 4의 일반형 130 규격을 시각적으로 연결한다.

==================================================
5. 가변형 문틀 현업 운영 규격
==================================================

사용자에게 실제 발주 담당자가 확인해 준 현행 운영 정보:

가변형 문틀:
60~250mm
5mm 단위 발주

사용자 확인에 따르면 영림 신규 책자 P360 도어프레임편에도 해당 내용이 기재되어 있다.

이 정보는 이번 영상의 현업 발주 정보로 사용한다.

단:
- 「혼합형 = 가변형」으로 단정하지 않는다.
- 기성폭과 가변형을 동일한 제품 분류 축처럼 설명하지 않는다.
- 이번 영상에서는 필요한 폭을 결정한 뒤 제품별 공급 규격을 확인한다는 발주 관점에서 설명한다.

6. 승인된 Scene 구조
==================================================

총 콘텐츠 Scene 6개 + 공통 대산 엔딩.

------------------------------
Scene 1 — Hook
------------------------------

역할:
벽체 두께만 알면 문틀 폭이 결정되는지 문제 제기.

TTS 방향:
「문틀 발주할 때, 벽 두께만 확인하고 계신가요?」

화면 자막:
벽 두께만 알면
문틀 폭 결정 끝?

화면:
- 벽체 단면
- 115mm 치수 표시
- 필요한 문틀 폭은 ?
- 대산이를 보조 설명자로 활용
- 첫 1~2초 안에 질문이 즉시 이해되어야 함

------------------------------
Scene 2 — 최종 마감 두께
------------------------------

역할:
벽체 자체의 두께만 보면 안 되는 이유 설명.

TTS 방향:
「현장에서는 벽체 두께만 보면 안 됩니다.」

화면 핵심:
벽체 두께만 확인 X
최종 마감 두께까지 확인

그래픽:
115mm 벽체
→ 타일 마감 추가
→ 마감 후 전체 두께가 달라지는 구조

보조 설명:
타일 등 마감재에 따라 최종 두께가 달라질 수 있음

금지:
벽체 + ○mm 같은 범용 계산 공식 생성 금지.

------------------------------
Scene 3 — 실제 발주 사례
------------------------------

역할:
실제 현업 사례로 이해시키는 핵심 Scene.

TTS 방향:
「실제 발주에서는 이렇게 달라질 수 있습니다.」

화면 핵심:
115 벽체 + 타일 마감
→ 발포문틀 130바 필요

그래픽 흐름:
115mm 벽체
↓
+ 타일 마감
↓
발포문틀 130mm

「115 → 130」만 단독으로 보여 범용 공식처럼 보이지 않게 한다.
타일 마감 조건을 계속 시각적으로 유지한다.

필요하면 작은 보조 설명:
「벽체 115mm = 항상 130mm라는 의미는 아님」

------------------------------
Scene 4 — 발포문틀 운영 규격
------------------------------

역할:
발포문틀은 정해진 운영 폭 중에서 선택한다는 실제 발주 정보 제공.

TTS 방향:
「발포문틀은 타입별 운영 규격도 함께 확인해야 합니다.」

화면 핵심:
발포문틀
정해진 운영 폭에서 선택

정보 그래픽:

일반형
110 · 130 · 140 · 155 · 175 · 195 · 210 · 230 · 245

와이드형
110 · 140 · 155 · 175 · 195 · 210 · 230 · 245

슬림와이드형
110 · 140 · 155 · 175 · 195 · 210 · 230 · 245

단위 mm.

일반형의 130만 accent 처리하여 Scene 3 사례와 연결.

숫자를 TTS로 전부 읽지 않는다.
저장해서 다시 볼 수 있는 B2B 규격표처럼 명확하게 만든다.

------------------------------
Scene 5 — 가변형 문틀
------------------------------

역할:
발포문틀과 다른 공급 규격 방식 설명.

TTS 방향:
「가변형은 필요한 폭에 맞춰 더 세분화해서 발주할 수 있습니다.」

화면 핵심:
가변형 문틀
60~250mm / 5mm 단위

그래픽:
60mm ━━━━━━━━━ 250mm
5mm 단위 tick 또는 단계 표현

보조 설명:
필요한 문틀 폭에 맞춰 발주

------------------------------
Scene 6 — 최종 발주 체크포인트
------------------------------

역할:
새로운 정보를 추가하지 않고 앞 내용을 한 번에 회수하여 자연스럽게 마무리.

TTS 방향:
「결국 문틀 폭은 벽체만 보지 말고, 마감 후 필요한 폭과 제품별 공급 규격까지 확인해서 발주하는 게 중요합니다.」

화면:

문틀 폭 발주 전
이 3가지는 꼭 확인

01 벽체 두께 ✓
02 최종 마감 두께 ✓
03 제품별 공급 규격 ✓

마지막 핵심 문구:
「현장에 필요한 문틀 폭으로 발주」

대산이는 설명/open-arms 계열 승인 모션을 보조적으로 사용 가능.

Scene 6 이후 Canonical 대산 공통 엔딩으로 연결.

==================================================
7. 디자인/연출 방향
==================================================

이번 콘텐츠는:
- 규격
- 치수
- 구조
- 발주 정보
가 핵심이므로 Main 디자인은 Linear 계열을 우선한다.

브랜드 UI 자체를 복제하지 말고:
- 정밀한 alignment
- 얇은 divider
- 명확한 정보 hierarchy
- 제한적인 accent
- 규격표 가독성
만 차용한다.

전체 영상은 정보형 Remotion 그래픽을 우선한다.

대산이는 주인공이 아니라 설명 보조자로 사용한다.
승인된 Motion Library를 재사용하고 새 AI 캐릭터를 생성하지 않는다.

TTS가 모든 내용을 설명하지 않는다.
이번 영상은 특히 화면 자막/정보 그래픽이 핵심 정보를 전달해야 한다.

무음 시청자도 Scene 1~6의 화면 정보만 보고 아래 흐름을 이해할 수 있어야 한다:

벽체만 보면 안 됨
→ 최종 마감 고려
→ 115벽체+타일 실제 사례
→ 발포문틀 타입별 운영 규격
→ 가변형 60~250 / 5mm 단위
→ 발주 체크포인트

9. 이번 단계 실행
==================================================

1. 최신 공통 실행 지침과 필요한 관련 가이드만 확인한다.
2. 기존 door-frame-order-tips-v1을 Slim Copy 참고 대상으로 확인한다.
3. 신규 2편 프로젝트를 Slim Copy 방식으로 준비한다.
4. Canonical 대산 공통 엔딩 세트를 최신 기준으로 포함한다.
5. 승인된 대산이 Motion Library/필요 자산을 프로젝트 내부로 복사한다.
6. 위 Scene 1~6 기획을 기준으로 구현 준비한다.
7. 먼저 TTS 문구를 실제 발화용으로 최소한만 다듬되, 화면 정보보다 과도하게 설명하지 않는다.
8. TTS 최종 문구와 Scene별 예상 구현안을 보고한다.
9. 이 단계에서는 이미지 생성하지 않는다.
10. 임의로 Cover/SNS/정리/Git 단계로 넘어가지 않는다.

작업 결과 보고:
- 신규 프로젝트 절대경로
- 확인한 공통 가이드
- Slim Copy 출처
- 복사한 공통 엔딩/대산이 자산
- Scene 1~6 최종 TTS 후보

불필요한 탐색과 장황한 설명 없이 위 범위만 수행한다.
