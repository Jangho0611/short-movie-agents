# 대산 Shorts — Blender 개념형 3D 제작 가이드

작성: 2026-10-30. 적용 근거: 영림 경첩 편 실제 소스·QA와 사용자 승인. 이 문서는 제작 방법을 정리하며 새 모델·영상 제작을 자동 승인하지 않는다.

## 1. 도구 선택과 승인 범위

| 필요 | 우선 방식 | 주의 |
|---|---|---|
| 실물 외형 소개, 확대·이동, 간단한 강조 | 공식/실물 사진 + Remotion 2.5D | 사진에 없는 후면을 회전으로 만들어내지 않는다 |
| 작은 평면 회전, 제한적 개념 모션 | 분리 이미지 레이어 + 축 기준 transform | 질감·조명이 고정되어 있고 큰 회전 시 얇은 판/면 소실 가능 |
| 두께·옆면·후면·가림 관계가 필요한 큰 개폐 | 승인된 개념형 Blender 3D | 후면 구조의 출처와 단순화 범위부터 승인 |
| 실제 기구 동작·간섭·치수·작동각 입증 | 제조사 CAD/도면/실물 검증 | Blender 영상만으로 검증 완료라 주장하지 않음 |

Blender는 제품 정확성을 자동 보장하지 않는다. 개념 모델, 실제 제품 사진, 공식 CAD를 구분한다. 좌용 제품이 우용으로 변환되는 것처럼 설명하지 않고, 공식 근거 없는 방향 판별법을 추가하지 않는다.

## 2. 자료와 검증 범위

공식 이미지·외형 도면의 출처, 모델명, 사진 사용 허락, 확인된 앞면·옆면·체결홀·치수를 먼저 기록한다. 사진 원근을 실제 치수로 간주하지 않는다. 후면·내부·스프링·댐퍼·체결 방식이 미확인이면 정밀 복제하지 말고 단순화 범위와 화면 안내를 정한다. 다른 모델 사진으로 대체하지 않는다.

새 작업 전 사용자에게 모델의 목적(개념/제품 재현), 사용할 자료, 보이지 않는 부분 처리, 모션 범위, 테스트 Scene을 확인받는다. 승인 전 새 모델·렌더를 실행하지 않는다. 테스트 승인 후에만 다른 Scene으로 확대한다.

## 3. 부품과 회전 중심 — 일반 권장 절차

1. 고정 부품과 움직이는 부품을 분리하고 알아볼 수 있게 이름을 붙인다.
2. 축의 위치·방향을 기준 좌표로 정한다. pivot/Empty를 실제로 참고한 축 위치에 놓고 해당 날개와 연결부를 parent한다.
3. 날개는 두께 있는 mesh로 만든다. 체결홀은 일관된 위치·개수로 뚫고 모서리를 필요한 만큼만 둥글게 한다. Boolean 결과의 구멍과 음영을 확인한다.
4. 접힘·중간·반대 펼침에서 축 연결, 가림, 면 소실, 겹침을 확인한다. 화면상 연결돼 보이는 것과 기계적으로 결합된 구조는 별개다.
5. 확인되지 않은 실제 mm를 부여하지 않는다. 개념 모델 단위와 제조사 치수는 별도 기록한다.

## 4. 애니메이션과 Scene 길이

승인 TTS의 실제 길이로 Scene 프레임 수를 결정한다. 시작 hold → 동작 → 접힘 hold → 반대 동작 → 끝 hold처럼 읽을 시간을 준다. 모션 때문에 TTS를 가속하거나 자르지 않는다. 각도는 ‘개념 연출값’과 ‘공식 작동 사양’을 분리한다.

Blender 1 시작 프레임과 Remotion 0 시작 프레임을 표로 대응시킨다. 보간 방식과 overshoot를 확인하고, API가 실패를 무시하도록 작성된 경우 보간 적용을 검증한 것으로 기록하지 않는다. 마지막 프레임의 시각과 전체 구간 길이(N/fps)는 다르다.

## 5. 금속 재질·조명

공식 사진에서 보이는 밝기·색기·하이라이트 폭·표면 명암을 먼저 비교한다. Base Color, Metallic, Roughness는 시각 튜닝값이며 제조사 재질명/도금 사양을 뜻하지 않는다. linear RGB와 화면 HEX도 동일하게 취급하지 않는다.

축에는 길쭉한 반사, 넓은 날개에는 부드러운 반사가 생기도록 광원의 크기·방향을 조정한다. 재질만 바꾸기보다 광원과 World를 함께 확인한다. 회전 중 반사 튐, 홀 주변 음영, 플라스틱/거울 같은 외관을 같은 프레임에서 비교한다. 재질 수정 작업이라면 형상·애니메이션·카메라를 잠그고 전후 비교한다.

## 6. 이번 영림 편에서 실제 사용한 값 — 고정 규칙 아님

- Blender 5.2.3 LTS(프로젝트 로그 기준), Cycles 24 samples, denoising, AgX.
- 고정 core 반경1.12/높이17.2, 슬리브 반경1.2/높이8.35, 날개4×0.3×7.65, 관통홀 각5개/총10개. 모두 모델 단위. 카운터싱크·내부 기구는 생략.
- 상부0→−90→−180°, 하부0→+90→+180°. Blender 키프레임1/7,28/34,58/76. 실제 제품 작동각 아님.
- v1: Base linear RGB(.56,.59,.62), Metallic .72, Roughness .28, DISK area lights.
- v2: Base linear RGB(.74,.74,.74), Metallic **.88**, 축·슬리브 Roughness **.23**, 날개 **.38**. World RGB(.75,.75,.75), strength .65.
- 중립 RGB(1,1,1) RECTANGLE 조명: Key 4×22/3200W/위치(−8,−12,5), Fill 8×18/2200W/(10,−8,3), Rim 6×16/1800W/(3,8,10). 장면 스케일에 종속된 값이다.
- ORTHO 카메라(7,−35,7), 원점 지향, ortho_scale21.5. 투명 RGBA PNG720×1000, 30fps, 76장. 최종 영상1080×1920. 이 해상도는 이번 화면 점유 크기에 맞춘 것이며 모든 Hero의 권장값이 아니다.

상세 v1/v2 조명 차이와 근거 경로는 [영상별 기록](../projects/younglim-flag-hinge-order-shorts/docs/26.10.30수정.md)의 Blender 추가 절을 참조한다.

## 7. Blender 렌더 → Remotion → 조립

1. 승인 모델의 버전별 .blend와 재현 스크립트를 보존한다. 실행 전에 저장 경로와 덮어쓰기 동작을 검사한다.
2. 새 버전 경로에서 대표 상태를 먼저 확인하고, 승인 범위에 맞게 PNG 시퀀스를 렌더한다. 배경/자막은 Remotion에서 별도로 처리한다.
3. Remotion은 Scene frame에 대응하는 PNG를 선택하고 승인 폰트·타이틀·자막·TTS를 배치한다. 제품 비율을 유지한다.
4. Scene별 N/fps 길이를 확인한다. AAC 꼬리 패딩과 컨테이너 길이 때문에 프레임 길이가 달라지지 않도록 검증하며 실제 발화를 자르지 않는다.
5. 승인 Scene은 재렌더 대신 기존 파일을 재사용한다. ffmpeg 영상 stream copy 조립 시 timebase를 통일하고 전 구간 디코딩 프레임을 비교한다. AAC 재인코딩이 있다면 오디오 바이트 동일이라고 보고하지 않는다.

영림 예시: `src/Scene1BlenderConceptV2.tsx`는 v2 PNG를 사용하며 v1 대비 경로만 변경됐다는 QA가 있다. `src/PreviewV2Scenes.tsx`에서 Scene 2는 18f 지연 후 재생하고 75f부터 최종 형태, Scene 5는 57f부터 최종 형태를 유지했다. 각 Scene 173/151프레임을 그대로 지키며 모션 반복 없이 재사용했다.

## 8. 실패·한계와 대응

| 실제 관찰/검토 | 대응과 기록 원칙 |
|---|---|
| 2.5D 테스트는 +24/−18° 후 복귀로 큰 개폐 요구에 부족 | 사용자 승인 후 두께 있는 개념형 3D로 전환 |
| 사진 평면에는 후면·측면이 없고 반사가 고정 | 작은 회전으로 제한하거나 별도 자료/개념 모델 승인. 큰 rotateY만으로 완료 처리 금지 |
| v1 금속 표현이 단순하다는 사용자 피드백 | v1 모델을 로드한 복사본에서 재질·중립 직사각 조명만 수정 |
| 접힘 시 날개와 홀이 좁게 보임 | 투영/가림과 실제 형상 손실을 구분, 중간 상태까지 확인 |
| 최초 Blender 로그에 crash, 별도 실행 로그에 렌더 성공 | 원인 미확정. 환경/권한/로그 확인 후 적절한 승인 절차, 원인 단정 금지 |
| AUTO_CLAMPED 설정 코드가 AttributeError를 무시 | 해당 설정의 실제 적용 여부를 별도로 검사. 의도와 검증 결과 구분 |
| 기존 QA JSON의 PENDING과 이후 사용자 승인 시점이 다름 | 과거 JSON 보존, 날짜형 기록에 최신 승인 범위 추가 |
| 재현 스크립트의 고정 경로가 기존 결과를 덮어쓸 수 있음 | 원본을 바로 재실행하지 말고 새 버전 복사본의 입출력 경로를 수정·확인 |

영림 v2 조정 스크립트는 1장 확인 렌더까지 수행하며 전체76장 렌더는 저장된 .blend의 별도 실행이다. 단일 스크립트가 최종 영상까지 자동 완성한다고 설명하지 않는다.

## 9. QA와 승인

- 시작/접힘/중간/반대 펼침/종료: 실루엣, 축 연결, 두께, 구멍, 가림, 면 소실, 반사 일관성.
- 자료 검증: 정확한 모델 여부, 공식 확인 부위/개념 부위, 치수 단위, 사용 권한. 모션 각도를 사양으로 오인할 라벨이 없는지 확인.
- 수정 무결성: 재질 수정이면 mesh/hash, modifier 설정, camera, 모든 프레임 transform 비교. 비교 대상에 포함되지 않은 속성까지 자동 보증하지 않음.
- 영상: 실제 프레임 수, 해상도/fps/코덱, 전체 디코딩, TTS 파일 해시·속도, 무음 길이, 자막 타이밍, 승인 엔딩 픽셀 일치.
- 자연스러운 모션과 발음은 기계적 PASS와 구분해 사용자 검토를 받는다. Scene 테스트 승인 → 확대 적용 → 전체 Preview 승인 순서. 승인되지 않은 모델을 다른 제품으로 재사용하지 않는다.

## 10. 소스 보존과 다른 영상 재사용

프로젝트 안에 `blender/<version>/`으로 .blend, 생성/수정 스크립트, README, 버전·입출력·렌더 로그와 불변성 QA를 함께 둔다. 원본 사진·공식 도면·개념 모델은 출처가 드러나도록 분리한다. Blender PNG는 `public/assets/images/`, Scene/Preview/Final은 `public/assets/video/`, 승인 재사용 Canonical만 `public/references/`에 둔다. `public/previews/`나 `output/`를 새로 만들지 않는다.

다른 영상에서는 필요한 소스만 Slim Copy하고 해당 프로젝트 내부 자산으로 참조한다. 제품·사용 권한·단순화 범위와 모델 적합성을 다시 확인한 뒤 새 버전으로 작업한다. 이번 수치와 모델을 일반 제품 사양으로 승격하지 않는다. 자료가 부족하면 필요한 자료와 대안을 보고하고 모델/영상 제작 승인을 기다린다.
