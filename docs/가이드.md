# Short Movie Agents 프로젝트 가이드

## 1. 시작하기 (로컬 실행 절차)

### 1-1. 프로젝트 폴더로 이동

터미널을 열고 다음 명령을 입력한다. 경로에 공백과 한글이 있으므로 전체 경로를 따옴표로 감싼다.

```bash
cd "/Users/zart/Library/Mobile Documents/com~apple~CloudDocs/프로젝트/ADK/adk-samples/python/agents/short-movie-agents"
```

### 1-2. 서버 재기동

먼저 8501번 포트를 사용 중인 기존 서버 프로세스를 종료한다.

```bash
lsof -ti:8501 | xargs kill -9
```

`lsof` 결과가 없다면 이미 서버가 꺼져 있는 상태이므로 그대로 다음 단계로 넘어가면 된다.

환경 변수를 불러온 뒤 ADK 웹 서버를 실행한다.

```bash
source .env
uv run adk web . --port 8501
```

터미널에서 서버를 다시 종료할 때는 `Ctrl+C`를 누른다.

### 1-3. 브라우저에서 세션 시작

1. 브라우저에서 `http://localhost:8501` 주소로 접속한다.
2. 앱 선택 메뉴에서 **app**을 선택한다.
3. **New Session**을 눌러 새 작업 세션을 만든다.
4. 원하는 15초 영상의 주제를 입력하고, director가 안내하는 스토리·각본·영상 생성 승인 절차를 따른다.

### 주의: iCloud 폴더에서 `--reload_agents` 사용 금지

이 프로젝트는 iCloud Drive의 `Mobile Documents` 안에 있다. iCloud는 파일을 동기화하면서 임시 파일, 메타데이터 변경, 반복된 파일 이벤트를 발생시킬 수 있다. `--reload_agents`는 이런 변경을 코드 수정으로 인식해 에이전트를 불필요하게 여러 번 재로드하거나 세션을 불안정하게 만들 수 있다. 따라서 이 프로젝트에서는 `--reload_agents`를 붙이지 않고, 프롬프트나 코드를 수정한 후 서버를 수동으로 재기동한다.

## 2. 이 프로젝트에서 정의한 제작 규칙

### 영상 구조

최종 영상은 세로형 9:16, 총 15초, 3개 장면으로 구성한다.

- **장면1 — 훅 (0~3초):** 첫 순간에 시선을 잡는 강렬한 문제나 장면
- **장면2 — 전개 (3~12초):** 상황의 진행과 해결 과정
- **장면3 — 엔딩 (12~15초):** 신뢰감 있는 마무리와 브랜드 오버레이

Veo가 생성하는 개별 장면은 기술적으로 8초일 수 있다. 이 경우 최종 15초 타임라인에 맞게 FFmpeg 조립 단계에서 각 영상을 잘라 사용한다.

### 홍보 모드

제품·브랜드·회사 홍보 요청은 다음 흐름을 따른다.

```text
문제 제기 → 제품을 통한 해결 → 신뢰감 있는 브랜드 마무리
```

### 브랜드 고정 정보

홍보 모드의 엔딩 오버레이는 다음 순서와 문구를 유지한다.

1. `대량구매는` — 작은 도입 문구
2. `대산` — 가장 큰 브랜드명
3. `GS건설 3년 연속 납품업체` — 신뢰 문구
4. `www.daesan.ai` — 웹사이트 주소

### 등장인물의 국적 명시

모든 Veo 영문 프롬프트에서 등장인물을 묘사할 때는 반드시 **Korean**을 명시한다.

- 허용: `a Korean construction worker`, `a Korean businessman`
- 금지: `a construction worker`, `a businessman` 처럼 인종을 특정하지 않은 표현

이 규칙은 장면별로 인물의 인종이 임의로 바뀌는 것을 막고, 한국 홍보 영상이라는 기획 의도와 시각적 일관성을 유지하기 위한 것이다.

### Veo 프롬프트 형식

각 장면은 다음 다섯 항목을 사용한다.

```text
## 장면 N (X-Y초)
- 샷: 샷 크기와 카메라 앵글
- 카메라 움직임: 트래킹, 푸시인, 고정 등
- 피사체/동작: 화면에 보이는 대상과 물리적 움직임
- 조명/분위기: 자연광, 역광, 색감, 분위기 등
- Veo Prompt (EN): 위 내용을 통합한 영어 문단
```

설명 항목은 한국어로 작성하고 `Veo Prompt (EN)`만 영어로 작성한다. 영문 프롬프트에는 `cinematic`, `shallow depth of field`, `9:16 vertical format` 같은 영상 품질과 형식 정보를 포함한다.

## 제작 규칙은 어디에 정의되어 있는가

이 프로젝트의 규칙은 코드(`.py`)가 아니라, `app/prompts/` 안의 TXT 지시문 파일에 자연어 문장으로 정의되어 있다.

- `app/prompts/story_agent.txt`
  → 15초 3장면 구조, 홍보 모드(문제 제기 → 해결 → 신뢰 마무리), 브랜드 고정 정보(대량구매는/대산/GS건설/URL), 자막·엔딩 오버레이 규칙

- `app/prompts/screenplay_agent.txt`
  → Veo 프롬프트 출력 형식(샷/카메라 움직임/피사체/조명/Veo Prompt EN), 인물 국적 `Korean` 명시 규칙

즉 **“규칙을 바꾸고 싶다”는 “이 두 TXT 파일의 문장을 수정한다”와 같은 의미**다. 코드를 건드릴 필요가 없다.

## 3. 프롬프트(.txt) 파일 위치와 역할

프롬프트 파일은 모두 `app/prompts/`에 있다. Python 코드를 바꾸지 않고도 이 파일들을 수정해 에이전트의 행동 규칙을 바꿀 수 있다.

| 파일명 | 역할 | 이런 걸 바꾸고 싶으면 여기 수정 |
| --- | --- | --- |
| `director_agent.txt` | 전체 대화 흐름과 PD 페르소나, 단계별 승인 절차를 정의 | 대화 톤, 질문 방식, 스토리·각본·영상 승인 절차를 바꿀 때 |
| `story_agent.txt` | 스토리, 홍보 모드, 장면 자막, 엔딩 오버레이를 생성 | 스토리 구조, 브랜드 정보, 자막 스타일을 바꿀 때 |
| `screenplay_agent.txt` | 승인된 스토리를 장면별 Veo 프롬프트로 변환 | 카메라·조명 묘사 방식, 영문 프롬프트 규격, 인물 국적 규칙을 바꿀 때 |
| `video_agent.txt` | 장면별 `video_generate` 도구 호출 규칙과 결과 저장 방식을 정의 | Veo 도구 호출 순서, 인자, 실패 처리 방식을 바꿀 때 |
| `storyboard_agent.txt` | 콘티 이미지 생성용 프롬프트. 현재 파이프라인에서 비활성화되어 미사용 | 나중에 콘티 생성 단계를 다시 활성화할 때 |
| `story_agent_desc.txt` | `story_agent`의 짧은 설명. 다른 에이전트가 `story_agent`를 언제 호출할지 판단하는 라우팅 정보 | `story_agent`가 담당하는 요청의 범위나 요약 설명을 바꿀 때 |
| `*.bak`, `*.bak_*` | 각 TXT 파일의 수정 전 원본 백업 | 프롬프트 수정 후 문제가 생기면 기존 내용을 확인하거나 복원할 때 |

백업에서 복원할 때는 백업 파일을 바로 덮어쓰기 전에 현재 파일도 다른 이름으로 백업해 두는 것이 안전하다.

## 4. 프로젝트 구조 (에이전트-툴 관계도)

### 전체 파이프라인

`app/agent.py`는 최상위 `director_agent`와 세 개의 활성 서브 에이전트를 연결해 전체 파이프라인을 정의한다. storyboard 단계는 현재 비활성화되어 있다.

```text
사용자
  ↓ 주제 입력·단계별 승인
director_agent
  ↓ 스토리 요청
story_agent      ← app/prompts/story_agent.txt가 생성 규칙을 결정
  ↓ 승인된 story 세션 상태
screenplay_agent ← app/prompts/screenplay_agent.txt가 Veo 프롬프트 규칙을 결정
  ↓ 승인된 screenplay 세션 상태
video_agent      ← app/prompts/video_agent.txt가 도구 호출 규칙을 결정
  ↓ video_generate(prompt, scene_number)
Gemini API → Veo 3.1 Lite → 로컬 MP4 저장
```

### 네 개 에이전트의 역할

| 에이전트 | 역할 | 주요 입력·출력 |
| --- | --- | --- |
| `director_agent` | 전체 작업을 지휘하고 각 단계마다 사용자 승인을 받는 PD | 사용자 요청 → 서브 에이전트 호출·승인 관리 |
| `story_agent` | 15초, 3장면 스토리와 자막·엔딩 오버레이 설계 | 제작 주제 → `story` 상태 |
| `screenplay_agent` | 스토리를 카메라·조명·피사체 정보가 포함된 영문 Veo 프롬프트로 변환 | `story` → `screenplay` 상태 |
| `video_agent` | 각 장면의 영문 프롬프트로 영상 생성 도구 호출 | `screenplay` → `video` 경로 목록 |

### `video_generate` 도구와 저장 방식

`app/video_agent.py`의 `video_generate` 함수는 장면별 영문 프롬프트와 장면 번호를 받는다. `google.genai.Client()`가 환경의 `GOOGLE_API_KEY` 또는 `GEMINI_API_KEY`를 사용해 Gemini API에 접속하고, `veo-3.1-lite-generate-preview` 모델을 호출한다. 각 호출은 9:16 비율의 8초 영상 하나를 생성한다.

생성된 파일은 현재 ADK 세션 ID를 폴더명으로 사용해 다음과 같이 저장한다.

```text
output/{세션ID}/scene_1.mp4
output/{세션ID}/scene_2.mp4
output/{세션ID}/scene_3.mp4
```

오늘 `video_agent.py`는 GCP Vertex AI와 ADC 인증에 의존하던 방식에서 **Gemini API 키 방식**으로 개조되었다. 덕분에 로컬 실행 시 GCP 프로젝트·리전·ADC 인증 없이 API 키로 Veo를 호출할 수 있다.

### 개별 장면과 최종본

- `output/{세션ID}/scene_N.mp4`: Veo가 생성한 개별 장면
- `output/final_*.mp4`: 장면을 자르고 연결하며 자막·오버레이·음원을 적용한 조립 완성본

`video_agent` 단계는 개별 장면까지 저장한다. 현재는 이 장면들을 한 개의 15초 영상으로 만드는 **수동 조립 단계**가 추가로 필요하다. 이 프로젝트에서는 `assemble_final_movie.sh`가 그 역할을 한다.
